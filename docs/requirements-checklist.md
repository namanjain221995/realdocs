# Requirements checklist

This table lists every requirement of the original assignment (the master prompt, sections 1 to 18)
and of the owner's later continuation requirements of 2026-11-11, one row each. For every row it says
how far the requirement is met, where it is implemented, and where it is checked.

How to read the status column:

- **done** means implemented and checked by an automated suite on the Linux build host (or, for
  documents, written and checked against the code).
- **done, NOT TESTED natively** means implemented, and covered at most by unit tests and Linux/Xvfb
  Electron runs. It was never run on Windows or macOS, so its real behaviour on those systems is
  unknown. This is the best status any native behaviour can have here.
- **partly** means part of the requirement is met; the row says which part is not.
- **not done** means it is not built, or it was not performed.

"Verified in" names the test file or suite. Counts and results are not repeated here; they are in
[testing.md](testing.md) ("see testing.md" in a row means the suites named there). Performance rows point to
[performance.md](performance.md). The Linux/Xvfb Electron runs are Linux smoke tests only; they say
nothing about Windows or macOS. No meeting application was tested with private mode on, so every
combination in [capture-compatibility.md](capture-compatibility.md) reads `NOT TESTED`.

Abbreviations for paths: `server` = `apps/server`, `web` = `apps/web`, `desktop` = `apps/desktop`,
`editor` = `packages/editor`, `contracts` = `packages/contracts`, `ui` = `packages/ui`.
