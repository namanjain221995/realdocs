# Security checklist

A checklist of the security requirements for the web app and API, the Electron desktop app, files and secrets,
with the status of each item and where it is implemented and tested. The narrative description of the design
is in [security.md](security.md); this document is the item-by-item view and the record of the review of
2026-11-12.

The owner's upgrade prompt is not stored in this repository, so the items below follow the list given for this
work and section 13 of `RealtimeDocs_Claude_Code_Master_Prompt.txt` ("Desktop and web security").

Status labels: **IMPLEMENTED AND VERIFIED**, **IMPLEMENTED BUT NOT NATIVE-TESTED**, **CONFIGURED BUT REQUIRES
CREDENTIAL**, **PARTIALLY IMPLEMENTED**, **BLOCKED WITH EXACT REASON**. Where a status is not one of these, the
item is **NOT IMPLEMENTED**, and the text says so.

"Verified" means a test in this repository exercises it on the Linux build host. It does not mean there was an
independent review or a penetration test: there was none. Test file names are under `apps/server/test/` unless
a path says otherwise.

## Security review of 2026-11-12

A review of the upgrade's code found five problems. All five were fixed the same day. Items 1 to 3 and 5
have a regression test that was located by search; for items 3 and 4 no test was found in `apps/server/test`
by a text search, which means **not verified by a located test**.

| #   | Finding                                                                                                                                                   | Fix                                                                                                                                                           | Test located                                                                                 |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 1   | A hostile heading level taken from the shared document could break or exhaust the admin revision diff                                                     | The level is clamped to 1 to 6 (`src/history/diff.ts`); a failing diff degrades instead of failing the request                                                | `unit/history.test.ts` "clamps a heading level taken from the shared document"               |
| 2   | The webhook SSRF filter missed IPv4-mapped IPv6 literals written in hexadecimal (`::ffff:7f00:1`)                                                         | Mapped addresses are decoded and checked as IPv4; 6to4 (`2002::/16`) is blocked (`src/service/webhook-security.ts`)                                           | `unit/service-api.test.ts` "classifies non-public addresses"                                 |
| 3   | In cluster mode, sockets waiting for their first frame were not counted against the connection cap, and the queue held while forwarding had no byte bound | The cap now counts sockets being routed; the pre-forward queue is bounded by frame count (64) and by bytes (twice the maximum frame) (`src/collab/server.ts`) | Not found by search. Covered in intent by `integration/cluster.test.ts`; not verified        |
| 4   | The `/metrics` token comparison could answer 500 and reveal the length of the token                                                                       | Both sides are hashed with SHA-256 and the digests compared in constant time (`src/http/app.ts`)                                                              | Not found by search. `integration/cluster.test.ts` uses a correct token only                 |
| 5   | Bidirectional isolates survived title sanitisation                                                                                                        | Every Unicode format character (category `Cf`) is removed from generated titles (`src/service/title.ts`)                                                      | `unit/service-api.test.ts` "removes every invisible format character from a generated title" |

Also done in the same review: the desktop app refuses an update whose version is not newer than the running one
(`isNewer` in `src/main/update-service.ts`); CI secrets are passed through `env:`; the scale overlay requires a
Redis password.

### Accepted and open

| Risk                                                                                                   | Why it is accepted, and what to do                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Redis is a trust root in multi-instance mode                                                           | Whoever can write to Redis can redirect sockets, read or forge tickets and clear limits. Keep it on a private network and set a password. The live deployment does not use Redis         |
| `TRUST_PROXY` must be a hop count, not `true`                                                          | The configuration accepts `true`, in which case the left-most `X-Forwarded-For` entry is believed and can be forged. Use the number of proxies (`1` for the live deployment)             |
| An idempotency claim older than 120 seconds can be taken over while the first request is still running | A very slow request can then create a duplicate session. The window is `STALE_CLAIM_SECONDS` in `src/service/idempotency.ts`                                                             |
| CI actions are pinned by tag, not by commit SHA                                                        | `actions/checkout@v4` and similar in `.github/workflows/*.yml`. A moved tag would change what runs. The workflows were not executed                                                      |
| Migration 0002 re-validates the `audit_events` CHECK under a brief exclusive lock                      | `DROP CONSTRAINT` then `ADD CONSTRAINT` on `audit_events` scans the table under `ACCESS EXCLUSIVE`. Brief while the table is small. It ran in 0.15 s on the rehearsal copy of 2026-11-12 |
| The sign-in limiter per account from anywhere is ten times the per-address limit                       | Defaults: 8 failures per account per address and 80 per account in total, per 15 minutes. A wide distributed attack can still lock an account for 15 minutes                             |
| Rate limits fail open when Redis is unreachable                                                        | A limiter that cannot count lets the request through and logs a warning, so a Redis restart is not an outage of sign-in. The exposure is a short period without throttling               |

Other limits that are stated elsewhere and still hold: no malware scanning, no multi-factor authentication,
an editor can deny service to readers of the same document, backups are unencrypted, and share links are bearer
capabilities ([security.md](security.md), "Known limitations" and "Residual risks"; the statement there that
rate limits are per process and in memory is true only without `REDIS_URL`).

## Credential rotation checklist

Rotate on suspicion, on staff change, and on a schedule you choose. Record the date. None of these rotations
was performed on the live deployment by this work; "Rehearsed" says whether the steps were run anywhere.
